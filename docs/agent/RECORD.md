# Record and view

**Read when:** inspecting a run, changing event fields, resuming a run, or
debugging an interrupted/corrupt record.
**Source of truth:** `manifest.record`, `harness/recschema.py`,
`harness/recread.py`, `harness/recwrite.py`, `harness/view.py`.
**Verify:** `python3 run.py view --schema`, `python3 run.py view --list`,
`python3 -m unittest tests.test_recread tests.test_recwrite tests.test_view`.

## Paths and identity

```
.logs/runs/<run_id>/record.jsonl     append-only events; one JSON object per line
.logs/runs/<run_id>/record.lock      flock held by the live executor
.logs/runs/<run_id>/obs/             saved bytes for large text observations
.logs/run.lock                       tree-wide lock; one run per tree
```

`run_id` is `YYYYMMDDTHHMMSSmmmZ-<8 lowercase hex>`. Lexicographic order equals
chronological order; the newest run is `max(run_id)`. `record.resolve()` chooses
the newest record when no id is given and rejects unknown ids.

## Line format

One canonical JSON object per line, UTF-8, LF terminated, no embedded newline:

```json
{"schema":"loop-record/1","v":1,"run_id":"20240101T000000000Z-abcdef01","seq":1,"ts":"2024-01-01T00:00:00.000Z","type":"run_start","data":{"...":"..."}}
```

Rules enforced by `recschema.check()`:

- Envelope fields are exactly `schema`, `v`, `run_id`, `seq`, `ts`, `type`, `data`.
- `schema == "loop-record/1"`, `v == 1`, `run_id` matches the directory.
- `seq` is contiguous from 1 and is never reused.
- `data` fields are exactly the set declared for that event type.
- Unknown envelope or payload fields are corruption, not extensions.
- A final line without LF is a torn tail. The next writer truncates it; complete
  lines are never modified.

## Events

| Type | Terminal | Payload |
| --- | --- | --- |
| `run_start` | no | `task` str, `root` str, `entrypoint` str, `model` str, `tools` list<str>, `max_inline` int, `record_source` str |
| `turn` | no | `turn` int, `finish_reason` str\|null, `usage` usage, `message` message, `calls` list<call>, `done` done\|null |
| `resume` | no | `from_seq` int, `turn` int, `messages` int, `root` str, `by` str |
| `error` | no | `code` int, `text` str, `finish` str |
| `interrupted` | terminal marker | `reason` str, `last_seq` int, `by` str |
| `end` | yes | `exit` int, `finish` str, `result` str\|null, `turns` int, `hit` int, `miss` int, `out` int, `reasoning_c` int, `cost` num |

Nested types:

| Type | Fields |
| --- | --- |
| `usage` | `hit` int, `miss` int, `out` int, `reasoning_c` int, `cost` num |
| `message` | `role` str, `content` str\|null, `tool_calls` list<tool_call> |
| `tool_call` | `id` str, `type` str, `function` fn |
| `fn` | `name` str, `arguments` str |
| `call` | `id` str, `name` str, `observation` str, `bytes` int, `saved` str\|null |
| `done` | `id` str, `result` str |

The production loop stores assistant `content` as `null`; it has no text
channel. A `done` call appears on the assistant message but is not appended as a
`call`: `turn.done` records it and the run ends. A turn with no tool call also
ends the run, with `finish=no_tool_call`.

## Derived state

```
empty        no events
interrupted  any last event other than end
complete     last event is end
```

`end` is the only completion marker. An `interrupted` event is a useful marker
of who noticed the death and why (`server_start`, `server_stop`, `worker_lost`),
but the state is already `interrupted` when `end` is absent. A kill -9 leaves no
marker.

`view.render()` adds derived lines that are not stored in the record:

- `[interrupted] reason=no_terminal_event ...` when the last event is not
  `interrupted` and the state is not complete.
- `[torn] bytes=N dropped=1` when the reader found a partial trailing line.

## Folding the record into messages

`agent.context(events, task)` is the only fold:

```
[
  {"role":"system","content":api.header()},
  {"role":"user","content":task},
  for each turn event:
    turn.data.message,
    for each call in turn.data.calls:
      {"role":"tool","tool_call_id":call.id,"content":call.observation}
]
```

Important: the system header is regenerated by `api.header()` from current
config on each fold. `run_start.max_inline` is recorded metadata for audit; it
is not substituted into the header. A resume therefore sees the current header,
not necessarily the byte-identical header of the original run.

`resume` rebuilds this list and continues. It never replays prior tool calls.

## Writer

Only `recwrite.Writer` appends. Construction and append behavior:

1. Validate `run_id`; create `.logs/runs/<run_id>/`.
2. Take `record.lock` with `flock(LOCK_EX|LOCK_NB)`; raise `record.Busy` if held.
3. Read existing events; compute `seq`; if the tail is torn, `ftruncate` it and
   fsync.
4. `append(type, data)`: validate against `manifest.record`, serialize canonical
   JSON + LF, `O_APPEND` write the whole line, `fsync`, increment `seq`.
5. `seal()` makes later appends raise `record.Sealed`. `close()` seals and
   releases the file descriptors.
6. `interrupt(reason, by)` appends one `interrupted` event only if the writer is
   not sealed and the last event is neither `end` nor `interrupted`.

Crash safety: one fsynced line per event. A kill loses at most the in-flight
turn. Complete lines are never rewritten. `end` is never inferred.

## Reconcile

`recwrite.reconcile(reason, by, run_id=None)` scans all records (or one):

1. Skip corrupt records; they are never rewritten.
2. Skip complete records.
3. Try a `Writer`; skip a record whose lock is held by a live executor.
4. Append one `interrupted` event if the last event is not terminal.

The daemon runs this at start and the supervisor runs it for a lost worker.

## View

`view` is a pure function of record bytes: no server, network, clock or cwd.

```sh
python3 run.py view --list                 # every record on disk with state
python3 run.py view --list --json          # {"kind":"list","runs":[...]}
python3 run.py view RUN_ID                 # compact text, one group per event
python3 run.py view RUN_ID --json          # canonical loop-view/1 document
python3 run.py view --json RUN_ID | python3 run.py view -
python3 run.py view --schema               # manifest.record as JSON
```

The `loop-view/1` envelope is exactly:

```
schema, version, run_id, source_schema, source_version, state, seq,
torn_tail_bytes, events
```

The input form of `view -` is validated: fields, schema/version, every event,
and the declared `state` must match the events. Text limits live in
`manifest.record.view.text_limits`: args 180, err 300, obs 400, task 200 and
text 300 characters. Newlines, carriage returns and tabs are escaped.

Exit codes: `0` rendered, `2` no such run, corrupt record or usage error.

## Resume

```sh
python3 run.py view --list          # find a non-complete run
python3 run.py resume RUN_ID        # costs tokens; network required
```

`resume` refuses:

- a complete run (last event is `end`) with exit 2;
- a corrupt record with exit 2;
- a tree whose `.logs/run.lock` is held, or a record lock held by another
  process, with exit 5.

It acquires the tree lock, opens a `Writer`, appends one `resume` event, then
runs the same agent loop and appends `turn*` and eventually `end`. If the
recorded root is missing it falls back to `config.root()` and says so on stderr.
`resume` is not part of the control plane.
