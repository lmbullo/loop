# Agent protocol

The production loop exposes four tools. This file is the wire contract an agent
sees, not an implementation guide.

## System header

Every run starts with a system message generated by `harness.api.header()`.
It states the append-only rule, the one-run-per-tree rule, literal argv, the
cost model, the absence of a text channel, the inline observation limit and the
tool signatures. The header is rebuilt at `run_start.max_inline` and refreshed
at a soft reload boundary.

## Tools

### `exec`

```
exec(argv: [str], cwd?: str, stdin?: str, timeout_ms?: int) -> observation
```

- Spawns argv directly. No shell, no globs, no pipes, no redirects.
- Use `["sh","-c","..."]` when a shell is actually required.
- `cwd` is resolved against the run's sandbox root when relative.
- Default timeout is 120000 ms. A timeout kills the process group and reports
  `code=TIMEOUT`.
- Output is `exit=<code> ms=<dur>` followed by stdout and an optional
  `--stderr--` section.

### `write`

```
write(path: str, data: str, append?: bool) -> observation
```

- Writes UTF-8. Replaces by default; `append=true` appends.
- Reports the new byte count and whether it replaced or appended.
- Creates parent directories.

### `edit`

```
edit(path: str, old: str, new: str) -> observation
```

- Replaces exactly one occurrence. Zero or multiple matches is an error, not a
  silent choice.
- Returns a small before/after context window.
- Use `write` for a full rewrite; use `edit` for a surgical change.

### `done`

```
done(result: str) -> observation
```

- Terminates the run. The result is recorded in the `done` and `end` events.
- `done` is not dispatched as a tool call; it ends the turn loop.

## Observation bounding

The production wire keeps up to `max_inline` bytes inline. Larger text becomes:

```
kind=text bytes=<n> lines=<n> saved=<run-relative path>
first15:
  ...
last5:
  ...
```

Binary output becomes a digest (`kind=binary bytes=... sha256=... head_hex=...`).
The full bytes are always saved under `.logs/runs/<run_id>/obs/`. Read the
saved file in ranges; do not dump it back into the message list.

## Message list

- Append-only. Earlier entries are never edited, reordered or re-sent in a new
  form.
- Each turn appends one assistant message and one tool message per call.
- Assistant text is not recorded and not re-sent. Only tool calls and their
  observations persist.
- A turn with no tool call ends the run with `finish=no_tool_call`.
- Reasoning is never re-sent; it is counted in the usage record.

## Cost

The whole message list is re-sent each turn. The unchanged prefix is a cache
hit; only the appended suffix is a cache miss. Output tokens bill highest.
Reasoning tokens are billed once but cost nothing to re-send. Rates live in
`manifest.cost_model.pricing_per_1M`.

## Failure responses

Tool errors are observations, not crashes:

```
err malformed_arguments <detail>
err harness <TypeName>: <detail>; exec argv, write path+data, edit path+old+new
err bad_args write requires data:str, got NoneType
err match=0 expected=1
```

The model decides whether to retry. The harness never hides a failed tool call.

## Commit protocol for coding agents

When this loop is used to change a repository:

1. Read `AGENTS.md` and `manifest.json` first.
2. Prefer `exec` with `git status`, `git diff`, tests and linters.
3. Use `edit` for surgical changes and `write` for new files.
4. Run the repository's offline verification before `done`.
5. Finish with a conventional commit subject and `why:`/`check:` body lines.
6. Call `done` with a one-line result naming the verification command.
